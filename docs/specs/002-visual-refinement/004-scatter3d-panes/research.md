# scatter3d-panes — 調査ログ

## 1. 参考画像 3 枚から読み取ったこと(2026-09-07)

中継役から渡された参考画像 3 枚(request.md §2.2 の参考サイトの画面。第三者のサイトの画面でありリポジトリに置かない)を本セッションが見て読み取った。画像は横 1600 px・プロット領域の高さおよそ 1150 px。数値は目視の見積もりで、仕様に落とすための粒度に留める。

### 1.1. パネル(面)

- 縦の面は **1 枚だけ**で、点群の立方体のひとつの縦面に貼り付いている。視点が変わると画面上の位置が変わる(1 枚目: 右側で斜め、2 枚目: 正面奥、3 枚目: 左側で斜め)。画面に固定されておらず、点群と同じ回転で動く。
- 底面(床)の面は 3 枚とも立方体の底に張られ、縦の面と底面で「箱の角」を作る。
- 面の塗りはほぼ透明(背景との差が見えない程度。面の内側と外側の明るさの差は数 % 以下)。面の存在は、縁の線・格子線・影で読める。
- 面の縁は幅 1 px 程度の白〜淡い灰の線で、不透明度はおよそ 40〜50 %。格子線より明るい。
- 立方体の残りの稜線(手前側の縦の辺・上面の辺)は描かれていない。ワイヤーフレームの箱ではなく、縦 1 面 + 床の 2 面だけが線を持つ。
- 参考サイトには「Hide back pane」の切り替えがある(#2 spec `research.md` §1)。「back pane」の語から、縦の面は「背面」として 1 枚扱いだと読める。

### 1.2. 格子

- 縦の面・底面とも **3 × 3 のセル**(縦横それぞれ 4 本の線 = 縁 2 本 + 内側 2 本)。2 枚目では背面の内側の縦線 2 本と、目盛り `1.35`・`0.62` の高さの横線 2 本が見える。
- 線幅は 1 px 程度、色は白〜淡い灰、不透明度はおよそ 20〜35 %。点(1〜2 px、明るい色)より暗く、点を隠していない。
- 格子線は面の中だけに引かれ、面の外へ伸びない。

### 1.3. 目盛りと軸名

- 縦軸の目盛り: `2.08`・`1.35`・`0.62`・`-0.10` の 4 値(等間隔。間隔は 0.72〜0.73)。背面の外側の縦の辺のすぐ外に、辺に沿って上から下へ並ぶ。文字は太字のサンセリフ、高さはプロット領域の高さのおよそ 2.5 %(1150 px に対し 28〜30 px)。色は白、不透明度はおよそ 85〜95 %。
- 軸名 `Elevation`: 縦軸の目盛りの列の中(`1.35` と `0.62` の間)に、目盛りと同じ書体・同じ大きさで置かれる。
- 底面の目盛り: `1.08`・`0.36`・`-0.36`・`-1.09` の 4 値(等間隔。間隔は 0.72〜0.73)。床の辺の外に、辺に沿って並ぶ。文字は縦軸より小さく(高さおよそ 1.5〜1.8 %、16〜20 px)、斜体に見える(面に沿って歪んでいるため)。1 枚目は左手前の辺、3 枚目は右奥の辺と左手前の辺に見える。
- 文字は**面に沿って歪む**。3 枚目の左端で `vation` と `0.62` が縦に潰れ、床の `1.08`・`-0.10` が床の傾きに沿って斜めになっている。画面に固定した直立の文字ではない。
- 文字はどの画像でも左から右へ読める(鏡像になっていない)。
- 値の範囲: 縦軸は -0.10〜2.08、床は -1.09〜1.08。点群の座標系(-1〜1)そのものではなく、それらしい値域に写している。

### 1.4. 影(点群の面への投影)

- 3 枚すべてで、縦の面に点群の投影が写る(1 枚目: 地形と球の輪郭が桃〜白で、2 枚目: 地形の峰が青〜黄で、3 枚目: 地形と球が緑〜赤で)。
- 影は点の色を保ったまま暗く(不透明度およそ 30〜45 %)、点と同じ 1〜2 px の粒で描かれる。単色の塗りつぶしではなく、点群の色の勾配が影にも残る。
- 底面にも投影が写る(1 枚目の床に地形の足跡が桃〜白の粒で見える)。
- 影は面の中に収まり、面の外へ出ない。

### 1.5. 背景の地

- 一様な黒ではなく、深い青(おおよそ #06101e〜#0c1f3a の範囲)に、雲のようなむら(低周波のノイズ)がある。むらの明暗差は小さく(輝度でおよそ 3〜6 %)、粒は無い。
- 3 枚で同じテクスチャに見える(視点を変えても背景は動かない)。
- プロット領域の外(見出しの帯)は黒で、プロット領域だけが青い。

## 2. 既存コードの事実(2026-09-07 に実物で確認)

- `frontend/src/lib/project.ts`: `projectPoint`(器渡し)と `projectPoints`(一括)は同じ式を持つ(ヨー → ピッチ → `FOCAL = 3.2` の透視投影、`FILL = 0.78`)。unit #3 の最終検証パネルが「片方を変えたら両方を追従させること」と申し送っている。
- **既定ピッチ `SCATTER_PITCH = -0.42` は、床を下から見上げる向きである。** 本セッションが同じ式で計算した: yaw 0・pitch -0.42 で床(y = -1)の手前の辺(z = 1)は sy 528、奥の辺(z = -1)は sy 593 と、奥の辺が画面で下に来る(depth は手前 1.32・奥 -0.51)。pitch +0.42 では手前 sy 691・奥 sy 413 と、奥の辺が上に来る(上から見下ろす)。`project.ts` のコメント「点群を斜め上から見た画にする」と実際の向きが食い違う。点群だけでは気づきにくいが、床のパネルと格子を描くと視点の向きが露わになる(参考画像はいずれも水平〜上からの視点)。
- 背面の壁の選択則: 4 つの縦面の外向き法線をヨーで回した z 成分は `x=+1: -sin(yaw)`・`x=-1: +sin(yaw)`・`z=+1: +cos(yaw)`・`z=-1: -cos(yaw)`。ピッチは `cos(pitch) > 0`(可動範囲 ±1.45 rad)を掛けるだけで順序を変えない。z 成分が負の 2 面が「奥向き」で、順序が入れ替わるのは yaw が 90° の倍数のときに限られ、そのとき入れ替わる 2 面はどちらも真横(投影が線になる)を向いている。したがって 2 面を選ぶ方式では入れ替わりの瞬間に画の飛びが出ない。1 面だけを選ぶ方式では yaw 45° + 90°k で最も奥の面が入れ替わり、そのとき両面とも斜め 45° で見えているため画が飛ぶ。
- `frontend/src/lib/axes.ts`: `AXIS_SEGMENTS`(`axis` 3 本・`edge` 12 本)と `Vec3` を export し、`project.ts` が `Vec3` を import する。`axes.test.ts` が 15 本・3 軸の端点・稜線の頂点・重複無しを検証する(#2 spec Requirement 4.1〜4.2)。
- `frontend/src/components/Scatter3DPanel.tsx`: 描画順は 背景(`fillRect` 1 回)→ 軸線 15 本(1 本ずつ `beginPath`/`stroke`、`globalAlpha` を奥行きで変える)→ 点(576 バケットの counting sort、`fillRect`)。色はマウント時に `readToken` で解決し、パレットは `buildPalettes` で 1 度だけ作る。器 `axisFrom`・`axisTo` は effect の寿命で作る。点群の長さが変わったときだけ `allocateBuffers` で作り直す。
- `frontend/src/lib/palette.ts`: `parseHex`・`rotateHue`・`buildRamp`(不透明度を `rgba()` に焼き込む)。`rgba(` の文字列テンプレートはここ 1 箇所に限る規律(unit #3 tasks.md Global Constraints)。
- `frontend/src/app/globals.css`: `@theme static` に `--color-surface-1: #171d28`(現在の散布図の背景)、`--color-border`・`--color-text-dim`(軸線)、`--color-scatter-*` 7 個(停止色)がある。
- 計測(unit #3 完了時、HEAD `aa6a252`、13 回の出力): 5 パネルとも p95 17.0〜18.0 ms・mean 16.7 ms・max 19〜25 ms。unit #3 の観察: 点を 256 から 6,000 へ増やしても p95 は同等で max は改善した。`arc`・比較ソート・`fillStyle` の切り替え回数を増やす設計は避ける(unit #3 tasks.md Implementation Notes)。
- 計測器は rAF のコールバックの間隔を測る(`recordFrame(PANEL_NAME, nowMs)`)。p95 が rAF の周期(16.7 ms)に張り付いているのは「フレームが遅れていない」ことを示すが、1 フレームの作業時間そのものと余裕の量は分からない。
- `frontend/package.json`: `test` は `node --test "src/lib/**/*.test.ts"`。Node.js は v24.16.0。テストの対象は `wailsjs`・DOM・React を import しない純粋なモジュールに限る(#2 spec §3 前提 7)。
- Canvas 2D の文字描画(`fillText`)はフレームごとにグリフをラスタライズする。文字列が固定なら、マウント時にオフスクリーンの canvas へ 1 度描いておき、毎フレームは `setTransform` + `drawImage` で面に沿って貼るほうが安い(`drawImage` はアフィン変換に従う)。
- 用語集 `docs/glossary.md` は無い。名前は既存コードの語彙(`Vec3`・`Projected`・`ProjectedCloud`・`Orbit`・帯・段・バケット)に合わせる。

## 3. 参考画像から仕様へ落とすときの読み替え

- 参考は縦 1 面 + 床。本 unit の点群は自動回転で 26 秒に 1 周するため、縦 1 面を固定すると半周は面が手前に来て点群を覆い、文字が鏡像になる。§2 の選択則により「奥向きの縦 2 面 + 床」とすれば、面はつねに点群の奥にあり、入れ替わりの瞬間に画が飛ばない。参考と面の数が違うことは spec §3 前提に書く。
- 参考の格子は 3 × 3。unit #2 でユーザーが「格子は点の視認を妨げる」として退けた経緯があるため、分割数はこれ以上増やさず、線は 1 px・不透明度 0.2 以下に留める。
- 参考の文字は縦軸 4 値 + `Elevation`、床 2 軸 × 4 値。roadmap 前提節の「数値 4〜5 個と軸名 1〜2 語」は縦軸 4 値 + `Elevation` で逐語に満たせる。床の目盛りを足すと 8 値になり、逐語の上限を超える(spec §3 前提で人間の判断に委ねる)。
- 参考の値域(-0.10〜2.08、-1.09〜1.08)は点群の座標系 -1〜1 のアフィン写像として再現できる(`v = lo + (c + 1) / 2 × (hi − lo)`)。値域を Go 側から送る必要は無い(値は固定であり、送っても表示は変わらない)。
- 影は「点の色を保ったまま暗く」が参考の見え方。バケットごとに `fillStyle` を切り替える現行の方式を影にそのまま使うと切り替えが 576 × 面数に増えるため、影は段数を 8 に落とした別の表(構造 × 8 段 = 24 バケット)で描く。

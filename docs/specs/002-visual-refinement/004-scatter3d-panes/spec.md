# scatter3d-panes — 仕様

## 1. 目的と背景

roadmap `002-visual-refinement` の unit #4。unit #3(`scatter3d-pointcloud`)の完了時点で、3D 散布図は 6,000 点の地形・球・トーラスを高さに応じた色で描き、ドラッグで視点を変えられるが、点群は「原点を通る 3 軸と立方体の稜線 12 本」の上に浮いており、背景は `--color-surface-1` のべた塗りである。ユーザーは配布ビルドを中継役から渡された参考画像 3 枚(request.md §2.2 の参考サイトの画面。2026-09-06)と見比べ、残る差として「背面と底面のパネルと格子」「目盛りの数値と軸名」「点群の面への投影(影)」「むらのある深い青の背景」の 4 点を挙げた(roadmap §1 #4)。本 unit はこの 4 点を扱う。

参考画像から読み取った目標の具体は `research.md` §1 にある(画像はリポジトリに置かない。観察は 2026-09-07 に本セッションが行った)。要点は次のとおり。

- 縦の面 1 枚と床が立方体の面に貼り付き、視点と一緒に回る。面の塗りはほぼ透明で、縁(1 px・不透明度 40〜50 %)と 3 × 3 の格子(1 px・不透明度 20〜35 %)で面が読める。
- 縦軸に目盛り 4 値(`2.08`・`1.35`・`0.62`・`-0.10`)と軸名 `Elevation`、床に目盛り 4 値(`1.08`・`0.36`・`-0.36`・`-1.09`)。文字は面に沿って歪み、鏡像にならない。本書の目盛りは参考の両端 `[-0.10, 2.08]` を 3 等分した値を `toFixed(2)` で書くため、2 番目が参考の `0.62` ではなく `0.63` になる(参考の刻みを逐語に再現しない)。
- 点群の投影が縦の面と床に、点の色を保ったまま暗く(不透明度 30〜45 %)写る。
- 背景は深い青の低周波のノイズで、視点を変えても動かない。

要求の本体は `docs/specs/002-visual-refinement/request.md`(§番号で参照)、unit の範囲と完了条件は `docs/specs/002-visual-refinement/roadmap.md` §1・§1.1 にある。凍結済みの `docs/specs/001-dashboard-mvp/002-scatter3d-panel/spec.md`(以下「凍結 spec」)、完了済みの `docs/specs/002-visual-refinement/002-scatter3d-controls/spec.md`(以下「#2 spec」)・`003-scatter3d-pointcloud/spec.md`(以下「#3 spec」)が定めた契約のうち、本書が置き換えるものは §3 前提 1 と §8 に列挙する。

## 2. スコープ

### 対象(やること)

- パネルの幾何(縦 4 面 + 床)と、ヨーから奥向きの縦 2 面を選ぶ規則を、描画コンポーネントから切り出した純粋なモジュールとして定める(§5.2・§6.1)。unit #2 の `AXIS_SEGMENTS`(3 軸 + 稜線 12 本)をこのモジュールで置き換える
- 奥向きの縦 2 面と床に、透明に近い塗り・3 × 3 の格子・縁を描く(§6.3)
- 縦軸の目盛り 4 値と軸名 `Elevation` を、面に沿ったアフィン変換で貼る(§5.3・§6.2)。文字はマウント時にオフスクリーンへ描いた画像を毎フレーム `drawImage` する
- 点群を各パネルへ投影した影を、間引きと 8 段の色の表で描く(§5.4・§6.4)
- 背景を、マウント時に 1 度生成する低周波ノイズの画像(深い青 2 色の補間)に変える(§5.5・§6.5)
- 新しいトークン(背景 2 色・パネル 1 色・文字 1 色)を `globals.css` の `@theme` に足す(§6.6)
- TypeScript のテスト(面の選択・目盛りの値と書式・ラベルの変換・影の投影・ノイズの性質)と、`axes.test.ts` の置き換え(Requirement 1〜5)
- 完了時の p95・mean・max の計測と記録(Requirement 9)、配布ビルドの目視(Requirement 10)

### 対象外(やらないこと)

- ホイールによるズーム — 理由: request.md §4・roadmap §3 のスコープ外(承認済み)
- 原点を通る 3 軸の線 — 理由: 参考に無く、パネルの縁と格子が境界を示すため重複する(2026-09-06 にユーザーが決定。roadmap §1 #4 の指示)
- 立方体の残りの稜線(手前側の縦の辺・上面の辺) — 理由: 参考に無い(`research.md` §1.1)。パネルの縁 3 面ぶんだけが線を持つ
- 画面に固定した直立の文字 — 理由: 参考と同じく面に沿って歪ませるとユーザーが決定した(roadmap §1 #4)
- 床の面を視点に応じて上面へ切り替えること — 理由: ピッチはドラッグを離すと 1.5 秒で既定へ戻り(#2 spec §5.2)、下から見上げる時間が短い。切り替えの規則を足すより、床を固定して点の下に描くほうが単純
- 影の奥行き順・影どうしの重なりの制御 — 理由: 影は 1 px の粒で不透明度が低く、重なりは色の濃さとして読める
- 背景のアニメーション — 理由: 参考の背景は視点を変えても動かない(`research.md` §1.5)。毎フレームの生成は割り当てと負荷を増やす
- 点群の生成(Go 側)・転送形式・`ScatterPoint` の契約の変更 — 理由: 目盛りの値は座標系のアフィン写像で定まり、Go 側から送る情報が無い(§3 前提 4)
- 依存グラフ・他パネル — 理由: unit #5 の範囲(roadmap §1)
- 計測器の改修 — 理由: roadmap §3

## 4. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| パネル(pane) | 単位立方体の面に貼る薄い面。縦 4 面(`x = ±1`・`z = ±1`)と床(`y = -1`)の 5 枚を持ち、毎フレームそのうち 3 枚(奥向きの縦 2 面 + 床)を描く(§6.1) |
| 奥向き(back-facing) | 面の外向き法線をヨーで回した z 成分が負であること。カメラから見て面の裏側が見えている状態(§5.2) |
| 格子(grid) | パネルの内側を 3 × 3 に分ける線。各面で 2 方向 × 4 本(縁 2 本を含む)(§6.3) |
| 縁(edge) | パネルの外周の線。格子より明るい(§6.3) |
| 目盛り(tick) | 軸の値を示す数値の文字。縦軸(高さ)の 4 値(§6.2) |
| 軸名(axis name) | 軸の名前の文字。`Elevation` の 1 語(§6.2) |
| ラベル(label) | 目盛りと軸名の総称。面上の錨(anchor)と、面に沿う 2 方向(along・up)を持つ(§5.3) |
| 影(shadow) | 点群をパネルの面へ直交投影した点の集合。点の色を保ったまま暗い(§6.4) |
| 地(ground) | 枠の背景の画像。深い青 2 色を低周波のノイズで補間したもの(§6.5) |
| 錨(anchor) | ラベルを置く面上の 1 点(モデル座標)。文字の左端・ベースラインがここに来る |

## 5. 公開インターフェース(API)

ファイルの配置は本書では定めない(dev-decompose の責務)。Go 側の契約(#3 spec §5.1・§6.1〜§6.3)、`subscribeScatter`・`App.Snapshot`(凍結 spec §5.2〜§5.4)、視点の状態機械(#2 spec §5.2・§6.1)、`projectPoint`・`projectPoints`・`createProjectedCloud`(#3 spec §5.3)、パレット(#3 spec §5.4)は変えない。

### 5.1. `Scatter3DPanel`(TypeScript・React コンポーネント・既存の拡張)

- **定義**: `export function Scatter3DPanel(): React.JSX.Element`(シグネチャ・`'use client'`・ポインタ操作・購読は #3 spec §5.2 のまま)
- **事前条件**: #3 spec §5.2 と同じ(`Panel` の本文領域の内側でマウントされる)。
- **事後条件(本 unit で変わる部分)**:
  - 毎フレーム、視点を進めた後、§6.7 の順に描く: 地 → パネルの塗り → 格子と縁 → 影 → 点 → ラベル。3 軸と稜線は描かない。
  - 描くパネルは `selectBackWalls(orbit.yaw)`(§5.2)が返す縦 2 面と床の 3 枚。
  - 地・ラベルの画像・パネルの色文字列・影の色の表は、マウント時(地とラベルの画像は枠の寸法または `devicePixelRatio` の変化時にも)に作り、毎フレームは参照するだけ。
  - 毎フレームの描画で新しいオブジェクト・配列・関数・文字列を作らない(点群の長さが変わったときの器の作り直しと、寸法の変化時の地・ラベルの画像の作り直しを除く)。
  - 点群が空の間もパネル・格子・縁・ラベルを描く(#2 spec Requirement 4.7 の「軸線」をパネルに読み替えて引き継ぐ)。
- **エラー**: #3 spec §5.2 と同じ。トークンの解決に失敗した色は退避色(§6.6)で描き、描画を止めない。オフスクリーン canvas の 2D コンテキストを取得できない場合は、地を `--color-scatter-bg-low` のべた塗り(それも失敗すれば `transparent`)、ラベルを描かないことで退避し、`console.error` に記録する。

### 5.2. パネルの幾何(TypeScript・描画コンポーネントから分離した純粋なモジュール・#2 spec §6.2 の置き換え)

`node --test` で面の選択と影の投影を検証するため、DOM・React・`wailsjs` に依存しない。`Vec3` はこのモジュールが export し、`project.ts` の import 元になる(§3 前提 10)。

- **定義**:
  ```ts
  export type Vec3 = { x: number; y: number; z: number };
  export type WallId = 'xNeg' | 'xPos' | 'zNeg' | 'zPos';
  export type PaneId = WallId | 'floor';
  /** 面の幾何。origin + along × s + up × t(s, t ∈ [0, 2])が面上の点。corners は origin から along・up の順に回る 4 頂点。 */
  export type Pane = {
    id: PaneId;
    origin: Vec3; along: Vec3; up: Vec3;       // along・up は単位ベクトルで直交。up は縦面で (0,1,0)、床で (0,0,1)
    corners: readonly [Vec3, Vec3, Vec3, Vec3];
    /** 影の投影で固定する座標軸と値。xNeg なら axis 'x'・value -1。 */
    fixedAxis: 'x' | 'y' | 'z'; fixedValue: -1 | 1;
  };
  export const PANES: Readonly<Record<PaneId, Pane>>;
  export const GRID_DIVISIONS = 3;
  /** 奥向きの縦 2 面を、法線の回転後 z 成分の昇順(より奥が先)で返す。 */
  export function selectBackWalls(yaw: number, out: [WallId, WallId]): [WallId, WallId];
  /** 面上の格子線の端点(縁 2 本を含む 2 方向 × (GRID_DIVISIONS + 1) 本)を、pane の s・t の値の並びとして返す。モジュール定数。 */
  export const GRID_STOPS: readonly number[];   // [0, 2/3, 4/3, 2](長さ GRID_DIVISIONS + 1)
  ```
- **入力 / 出力**: `selectBackWalls` はヨー(ラジアン。正規化されていなくてよい)を受け、`out` に 2 面の識別子を書いて `out` 自身を返す。`PANES` は 5 面の幾何をモジュール定数として持ち、実行時に生成しない。
- **事前条件**: `yaw` は有限値。
- **事後条件**: `selectBackWalls` は同じ `yaw` につねに同じ 2 面を返す。返す 2 面の法線の回転後 z 成分(`xPos: -sin(yaw)`・`xNeg: +sin(yaw)`・`zPos: +cos(yaw)`・`zNeg: -cos(yaw)`)はどちらも 0 以下で、残る 2 面より小さいか等しい。`yaw` が `π/2` の整数倍のとき(2 面の値が 0 で等しいとき)は、識別子の辞書順で先の面を採る(決定的)。新しいオブジェクト・配列を作らない。`PANES` の各面の `corners` はすべて単位立方体の頂点(座標が ±1 の組)で、`origin + along × 2` と `origin + up × 2` が `corners` に含まれる。
- **エラー**: 返さない・投げない。`yaw` が NaN の場合は 0 とみなす(#2 spec §5.2 の入口の防波堤と同じ規律)。

### 5.3. ラベルの定義と面に沿った変換(TypeScript・純粋なモジュール)

- **定義**:
  ```ts
  export const ELEVATION_RANGE: readonly [number, number];  // [-0.10, 2.08]
  export const TICK_COUNT = 4;
  export const AXIS_NAME = 'Elevation';
  /** range を count − 1 等分した値。両端を含む昇順。 */
  export function tickValues(range: readonly [number, number], count: number): number[];
  /** 小数第 2 位までの文字列(toFixed(2))。負の 0 は "0.00" にする。 */
  export function formatTick(value: number): string;

  export type LabelKind = 'tick' | 'name';
  export type Label = {
    kind: LabelKind; text: string; fontPx: number;
    pane: PaneId;        // 貼り付ける面
    anchor: Vec3;        // 錨(モデル座標。面の外側でよい)
    along: Vec3;         // 文字の進む方向(面に沿う単位ベクトル)
    up: Vec3;            // 文字の高さの方向(面に沿う単位ベクトル。along と直交)
  };
  /** 縦軸のラベル(目盛り 4 個 + 軸名 1 個)を、wall の外側の縦の辺に沿って作る。マウント時に 1 度、または面の入れ替わり時に out へ書く。 */
  export function elevationLabels(wall: WallId, side: 'left' | 'right', out: Label[]): Label[];

  export type LabelFrame = { a: number; b: number; c: number; d: number; e: number; f: number; shrink: number };
  /** ラベルの錨における面の 2 方向の投影の微分からアフィン変換を作る。 */
  export function labelFrame(
    label: Label, yaw: number, pitch: number, view: { width: number; height: number },
    scratch: [Projected, Projected, Projected], out: LabelFrame,
  ): LabelFrame;
  ```
- **入力 / 出力**: `elevationLabels` は目盛り 4 個(`tickValues(ELEVATION_RANGE, TICK_COUNT)` を `formatTick` した文字列)と軸名 1 個の計 5 個のラベルを `out` に書く(長さ 5)。`side` は `wall` の `along` に対する左右(`left` = `origin` 側の縦の辺、`right` = `origin + along × 2` 側の縦の辺)。錨は `wall` の `side` 側の縦の辺から、面に沿って外側へ `LABEL_GAP = 0.06`(モデル座標)離れた位置(`left` なら `origin − along × LABEL_GAP`、`right` なら `origin + along × (2 + LABEL_GAP)` を通る縦の線上)で、目盛りは値の高さ(`y = -1 + 2 × k / 3`)、軸名は `y` の中央(0)に置く。`labelFrame` は `label.anchor`・`anchor + along × ε`・`anchor + up × ε`(`ε = 0.01`)を `projectPoint` で投影し、その差分を `ε` で割ってスクリーン上の単位ベクトル `(ax, ay)`・`(ux, uy)` を得る。`out` には `a = ax`・`b = ay`・`c = -ux`・`d = -uy`(canvas の y 軸は下向きなので up を反転)・`e = anchor の sx`・`f = anchor の sy` と、`shrink = |(ax, ay)| / (錨の scale)`(面の横方向の縮み。真正面で 1、真横で 0)を書く。
- **事前条件**: `view.width`・`view.height` が 0 より大きい。`scratch` は effect の寿命で作った器 3 個。
- **事後条件**: `labelFrame` は同じ引数につねに同じ値を書き、新しいオブジェクトを作らない。§6.1 の `along` の向きにより、奥向きの面のラベルでは `a ≥ 0`(文字が画面の左から右へ進む)。`a < 0` のラベル(奥向きでない面に貼った場合にだけ起きる)は描画側が描かない(鏡像を出さない。§6.2)。`tickValues([-0.10, 2.08], 4)` は `-0.10 + k × 2.18 / 3`(`k = 0..3`。誤差 1e-9 以内)、`formatTick` はそれぞれ `"-0.10"`・`"0.63"`・`"1.35"`・`"2.08"` を返す。
- **エラー**: 返さない・投げない。`yaw`・`pitch` が NaN の場合は 0 とみなす。

### 5.4. 影の投影(TypeScript・`project.ts` への追加)

- **定義**:
  ```ts
  /** points を、axis の座標を value に固定した面へ直交投影してから、projectPoints と同じ変換で out に書く。stride 個おきに 1 点を採る。 */
  export function projectPointsOnto(
    points: readonly Vec3[], axis: 'x' | 'y' | 'z', value: -1 | 1, stride: number,
    yaw: number, pitch: number, view: { width: number; height: number }, out: ProjectedCloud,
  ): void;
  ```
- **入力 / 出力**: `points[0], points[stride], points[2 × stride], …` の各点について、`axis` の成分を `value` に置き換えた点を #3 spec §5.3 と同じ式で投影し、`out.sx[j]`・`out.sy[j]`・`out.depth[j]`(`j` は採った順)に書き、`out.length` を採った点数(`ceil(points.length / stride)`)にする。
- **事前条件**: `stride` は 1 以上の整数。`out` の容量が `ceil(points.length / stride)` 以上。
- **事後条件**: 同じ引数につねに同じ値を書く。`out.sx[j]`・`out.sy[j]`・`out.depth[j]` は、`axis` の成分を `value` に置き換えた点を `projectPoint` に渡した結果と 1e-3 以内で一致する。三角関数は 1 回の呼び出しにつき 4 回だけ評価する。新しいオブジェクト・配列を作らない。
- **エラー**: 返さない・投げない。容量不足は `projectPoints` と同じく容量までに切り詰めて `console.error` に記録する。`stride` が 1 未満または非整数の場合は 1 として扱う。

### 5.5. 地のノイズ(TypeScript・純粋なモジュール)

- **定義**:
  ```ts
  export const NOISE_SIZE = 48;
  /** size × size の値ノイズ(0〜1)を決定的に作る。seed が同じなら同じ配列。 */
  export function buildNoise(size: number, seed: number): Float32Array;
  ```
- **入力 / 出力**: 長さ `size × size` の `Float32Array`。行優先。値は 0 以上 1 以下。
- **事前条件**: `size` は 2 以上の整数。`seed` は有限値。
- **事後条件**: 同じ `seed` につねに同じ配列を返す(疑似乱数は `Math.random` を使わず、`seed` から決定的に作る)。隣り合う要素(上下左右)の差の絶対値は 0.25 以下(低周波。粒に見えない)。値の最小と最大の差は 0.3 以上(むらが見える)。上下左右の端で隣接を循環させる(端の継ぎ目が出ない)。

## 6. データ構造

### 6.1. パネルの幾何(`PANES`。#2 spec §6.2 `AXIS_SEGMENTS` の置き換え)

| id | origin | along | up | fixedAxis / fixedValue |
| :-- | :-- | :-- | :-- | :-- |
| `xNeg` | (-1, -1, 1) | (0, 0, -1) | (0, 1, 0) | x / -1 |
| `xPos` | (1, -1, -1) | (0, 0, 1) | (0, 1, 0) | x / 1 |
| `zNeg` | (-1, -1, -1) | (1, 0, 0) | (0, 1, 0) | z / -1 |
| `zPos` | (1, -1, 1) | (-1, 0, 0) | (0, 1, 0) | z / 1 |
| `floor` | (-1, -1, -1) | (1, 0, 0) | (0, 0, 1) | y / -1 |

- **不変条件**: `along`・`up` は単位ベクトルで直交し、`origin + along × 2`・`origin + up × 2`・`origin + along × 2 + up × 2` が `corners` の残り 3 頂点。すべての頂点は単位立方体の頂点。縦 4 面の `along` は、面の内側(原点側)から見て左から右へ進む向きに取る(`along = n × up`。`n` は外向き法線)。`projectPoint` の式(`x1 = x cos yaw + z sin yaw`、画面右が `x1` の正)では `along` の回転後 x 成分が「その面の回転後の法線 z 成分の符号反転」に等しく、`selectBackWalls` が選ぶ奥向きの面(法線 z 成分 ≤ 0)ではつねに 0 以上になる。したがって描く面に貼った文字は、どの視点でも画面の左から右へ進み、鏡像にならない(§5.3 の `a < 0` は奥向きの面では起きず、防波堤としてだけ残す)。
- **ロジックの所在**: 奥向きの判定・格子線の端点・影の投影先の座標は §5.2・§5.4 のモジュールに集約する。`Scatter3DPanel` は識別子で面を引き、投影して描くだけ。
- **置き換え**: #2 spec §6.2 の `AXIS_SEGMENTS`(`axis` 3 本・`edge` 12 本)と `Segment` 型を廃する。

### 6.2. ラベル(§5.3)

- **縦軸の目盛り**: `ELEVATION_RANGE = [-0.10, 2.08]` を 3 等分した 4 値(両端を含む)。`k = 0..3` の目盛りの錨は `y = -1 + 2k/3`。文字は `formatTick` の結果(`-0.10`・`0.63`・`1.35`・`2.08`)。`fontPx = 13`、太字。
- **軸名**: `Elevation`。錨は `y = 0`(目盛り `0.63` と `1.35` の間)。`fontPx = 14`、太字。
- **貼る面と辺**: `selectBackWalls` が返す 2 面のうち、外側の縦の辺(2 面が接しない側の辺)の投影の `sx` が大きいほうの面・辺に貼る(画面の右側に来る。参考と同じ配置)。2 面の入れ替わりでラベルの面が変わるときだけ `elevationLabels` で `out` を書き直す(毎フレーム作らない)。
- **可読性の下限**: `labelFrame` の `a` が負のラベルは描かない(鏡像を出さない。§6.1 の向きにより奥向きの面では起きない)。`shrink` が 0.35 未満のラベルは描かない(真横に近い面の文字は潰れて読めず、汚れに見えるため)。`fontPx × scale` が 8 px 未満になるラベルも描かない。
- **画像**: 各ラベルの文字はマウント時に `OffscreenCanvas`(または `document.createElement('canvas')`)へ `devicePixelRatio` 倍の解像度で 1 度描く。書体は `bold {fontPx}px ui-sans-serif, system-ui, sans-serif`(参考の太字サンセリフ。等幅の `--font-mono` を使わないのは、数字の字幅が揃いすぎて参考の見え方から離れるため)。色は `--color-scatter-label`(§6.6)、不透明度 0.9。
- **不変条件**: ラベルは 5 個で固定(§3 前提 5)。文字列は英語(CLAUDE.md 言語規約)。

### 6.3. パネル・格子・縁の描画規則

- **塗り**: 各面の 4 頂点を `projectPoint` で投影し、1 つのパスを `fill` する。色は `--color-scatter-pane` に不透明度 0.06 を焼き込んだ `rgba()` 文字列(マウント時に作る)。
- **格子**: 各面で `GRID_STOPS` の内側の値(2/3・4/3)について、`along` 方向と `up` 方向の線を引く(内側 2 本 × 2 方向 = 4 本)。3 面 12 本を 1 つのパスにまとめて `stroke` 1 回。線幅 1 CSS px、色は `--color-scatter-pane` に不透明度 0.16。
- **縁**: 各面の外周 4 辺。3 面 12 辺(共有する辺は重ねて描いてよい)を 1 つのパスにまとめて `stroke` 1 回。線幅 1 CSS px、色は `--color-scatter-pane` に不透明度 0.45。
- **奥行きによる不透明度の変化は行わない**(#2 spec §3 前提 1 の置き換え)。描く面はつねに奥向きで、手前の線が無い。`globalAlpha` は触らず、不透明度は色文字列に焼き込む(#3 spec §6.4 の規律を線にも広げる)。
- **投影の器**: 面の頂点・格子線の端点の投影は `projectPoint` に effect の寿命で作った器を渡す。器の数は「頂点 4 個 + ラベルの微分用 3 個」で足り、格子線の端点は頂点の投影から線形補間で求める(面上の点の投影は透視で線形にならないが、縁の 2 点から 1/3・2/3 を取る誤差は格子線の太さ 1 px に対し 1〜3 px で、参考との見え方の差に現れない。端点を毎回投影する案は 2026-09-07 にユーザーが退けた)。投影は面ごとに頂点の 4 回に限る。

### 6.4. 影の描画規則

- **対象の面**: 描く 3 面すべて(奥向きの縦 2 面 + 床)。
- **間引き**: `SHADOW_STRIDE = 2`(点の半分)。
- **色**: 構造 × `SHADOW_STEPS = 8` 段の表。段 `s` の色は、構造のパレットと同じ停止色を 8 段に補間した RGB に `SHADOW_ALPHA = 0.22` を焼き込んだ `rgba()` 文字列。地形は位相ごとに表を持つ(36 位相 × 8 段)。表は `buildRamp` と同じモジュールに置く `buildShadowRamp(stops, steps, alpha): string[]` で作り、`rgba(` の文字列テンプレートがそのモジュールの外へ出ない規律を保つ。
- **バケット**: `shadowKey = S × SHADOW_STEPS + min(SHADOW_STEPS − 1, floor(C × SHADOW_STEPS))`(0〜23)。間引いた点について counting sort でバケット順に並べた添字の配列を 1 フレームに 1 度作り(器は点群の長さが変わったときだけ作り直す)、3 面で使い回す。面ごとに `projectPointsOnto` で投影し、バケットの昇順に `fillStyle` を 1 回ずつ設定して 1 CSS px の `fillRect` で描く。
- **不透明度の帯は持たない**(影は奥行きで変えない)。
- **点との関係**: 影は点より先に描く。点が影の上に載る。

### 6.5. 地(背景)の生成規則

- `buildNoise(NOISE_SIZE, NOISE_SEED)`(`NOISE_SEED = 20260907` の定数)の各値 `n` で、`--color-scatter-bg-low` と `--color-scatter-bg-high` を線形補間した色を、48 × 48 の `ImageData` に書き、オフスクリーン canvas へ `putImageData` する。
- 枠の寸法(CSS px × `devicePixelRatio`)のオフスクリーン canvas へ、`imageSmoothingEnabled = true` で拡大して `drawImage` する。この 2 段目の canvas を毎フレーム `drawImage` で枠へ写す(1 回)。
- 生成はマウント時と、枠の寸法または `devicePixelRatio` が変わったときだけ。
- `--color-surface-1` は散布図の背景として使わなくなる(トークンは他パネルが使うため残す)。

### 6.6. デザイントークン(CSS・`globals.css` の `@theme` への追加)

```css
/* 3D 散布図の地(背景)。深い青 2 色をノイズで補間する。 */
--color-scatter-bg-low:  #061024;
--color-scatter-bg-high: #0e2244;
/* パネルの塗り・格子・縁の基本色。不透明度は描画側で焼き込む(0.06 / 0.16 / 0.45)。 */
--color-scatter-pane:    #9fbcf0;
/* 目盛りと軸名の文字色。 */
--color-scatter-label:   #e8eef8;
```

- 色の直値は `globals.css` にだけ置く(凍結 spec Requirement 9.1 を維持)。不透明度の値(0.06・0.16・0.45・0.22・0.9)は色ではなく数値の定数として `.ts` に置く(#3 spec `BAND_ALPHA` と同じ扱い)。
- **退避**: いずれかのトークンが空文字または `parseHex` が `null` を返す文字列だった場合、地は `'transparent'`、パネル・格子・縁は `'gray'`、文字は `'white'` で描き、`console.error` に記録する(凍結 spec Requirement 9.2 と同じ退避色)。影の色は #3 spec §6.5 の停止色から作るため、その退避(`'white'`)に従う。

### 6.7. 描画順(1 フレーム)

1. 地(`drawImage` 1 回)
2. パネルの塗り(`fill` 3 回)
3. 格子(`stroke` 1 回)と縁(`stroke` 1 回)
4. 影(3 面 × 24 バケット以下の `fillStyle`、`fillRect` は 3 × ceil(点数 / 2) 回以下)
5. 点(#3 spec §6.4 のまま。576 バケット以下)
6. ラベル(5 個以下の `setTransform` + `drawImage`。描画の終わりに基底の変換行列へ戻す)

### 6.8. 既定ピッチ(`SCATTER_PITCH`)

`SCATTER_PITCH = +0.42`(#3 spec §5.3「既存値 -0.42 のまま」の置き換え。§3 前提 9)。`orbit.ts` はこの定数を import して初期値と復帰先に使うため、変更は `project.ts` の 1 箇所で済む。`PITCH_LIMIT`・`DRAG_RAD_PER_PX`・ドラッグの向きは変えない。

`project.ts` の `SCATTER_PITCH` のコメント「点群を斜め上から見た画にする」は、現状の値 `-0.42` では実際の画(床を下から見上げる)と食い違っている(§3 前提 9)。反転後は記述と値が一致するが、符号だけでは向きが読めないため、コメントに「正の値で床を上から見下ろす(奥の辺が画面で上に来る)」という符号と向きの対応を書き添える。値を変えるだけでコメントを直さない、という再発を防ぐための規定。

## 7. 振る舞い(受け入れ基準)

### Requirement 1: パネルの幾何と奥向きの面の選択

**対象**: §5.2 パネルの幾何 / §6.1 `PANES`

**受け入れ基準**:
1.1. システムは、`PANES` に縦 4 面と床の 5 面を持ち、各面の `corners` がすべて単位立方体の頂点で、`origin + along × 2`・`origin + up × 2`・`origin + along × 2 + up × 2` を含まなければならない。(常時)
1.2. `selectBackWalls(yaw, out)` が呼ばれたとき、システムは法線の回転後 z 成分が 0 以下の縦 2 面を、その成分の昇順で `out` に書き、`out` と同一の参照を返さなければならない。(イベント)
1.3. システムは、`yaw` が 0・π/2・π・3π/2 のちょうどのとき(2 面の成分が 0 で等しいとき)、識別子の辞書順で先の面を採らなければならない(同じ `yaw` につねに同じ結果)。(常時)
1.4. システムは、`yaw` を 0 から 2π まで 1° 刻みで進めたとき、`selectBackWalls` の結果が変わる `yaw` を π/2 の整数倍の前後 1° 以内に限らなければならない(入れ替わりが真横を向く瞬間に限られる)。(常時)
1.5. `yaw` が NaN の場合、システムは 0 として扱い、例外を投げてはならない。(異常系)
1.6. システムは、`selectBackWalls` と `PANES` の参照において新しいオブジェクト・配列を作ってはならない。(常時)
1.7. システムは、`GRID_DIVISIONS` を 3、`GRID_STOPS` を `[0, 2/3, 4/3, 2]`(各 1e-9 以内)にしなければならない。(常時)

### Requirement 2: パネル・格子・縁の描画

**対象**: §5.1 `Scatter3DPanel` / §6.3 パネル・格子・縁の描画規則

(2.1〜2.5・2.7 は `Scatter3DPanel.tsx` の静的検査、2.6 は点群の購読を止めた状態での目視で確かめる)

**受け入れ基準**:

## 8. 実現方針

- **面の選択(奥向きの縦 2 面 + 床)**: §3 前提 2。参考は縦 1 面だが、自動回転の下で飛びと鏡像を避けるための読み替え(2026-09-07 にユーザーが承認)。
- **格子線の端点**: §6.3。頂点 4 個の投影から線形補間する。器 7 個・投影 4 回/面で済み、誤差 1〜3 px は 1 px の線では見分けがつかない。
- **描画順と器**: 地 → 塗り → 格子・縁 → 影 → 点 → ラベル(§6.7)。線は `globalAlpha` を使わず、色文字列に不透明度を焼き込む。器は effect の寿命で 7 個(頂点 4 + ラベルの微分 3)、影の `ProjectedCloud` は 1 個を 3 面で使い回す(面ごとに投影 → 描画を順に行う)。
- **文字の画像化**: §3 前提 6。`fillText` を毎フレーム呼ばず、`drawImage` にアフィン変換を掛ける。透視の歪みは錨での微分で近似する。
- **影の色の表**: 点のパレット(64 段 × 3 帯)を影に流用すると `fillStyle` の切り替えが 3 面で 1,728 回になるため、8 段・帯なしの表(24 バケット)を別に持つ。間引き 2 は `fillRect` の増分を 9,000 回に抑えるため。
- **p95 が 20 ms を超えた、または max が 50 ms を超えたときの削る順**: (1) `SHADOW_STRIDE` を 2 → 4(影の `fillRect` を 4,500 回へ)、(2) 影を床だけに(縦 2 面の影を消す)、(3) `SHADOW_STEPS` を 8 → 1(構造ごとの単色。切り替え 3 回/面)、(4) 影を消す、(5) ラベルを目盛り 4 → 2(両端)へ。格子の分割数と点数は削らない(格子は参考の最小値、点数は unit #3 の契約)。いずれも受け入れ基準の数値(4.5・9.5・3.3)に触れるため、削る判断は人間に委ね、値の変更は spec の更新として行う。
- **既定ピッチの反転**: §3 前提 9。`project.ts` の定数 1 箇所の変更で、`orbit.ts` は import 経由で追従する。
- **`axes.ts` の置き換え**: `AXIS_SEGMENTS` を消し、`Vec3` をパネルのモジュールへ移す。`project.ts` の `import type { Vec3 }` の参照先が変わる。ファイル名の扱い(`axes.ts` を改名するか、新設して削除するか)は dev-decompose に委ねる。
- **参考画像**: 中継役から渡された参考画像 3 枚(request.md §2.2 の参考サイト)。WebGL の実装であり(#2 spec `research.md` §1)、同じ見た目への到達を完了条件にしない(roadmap §3)。
- 用語集(`docs/glossary.md`)はリポジトリに無い。名前は既存コードの語彙に合わせた。
